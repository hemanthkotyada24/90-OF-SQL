12 Core Commands
📋
01 · READ
SELECT
Select — Fetch Data
Used to retrieve data from one or more columns in a table.
showlist displayget data fetch records
SELECT column1, column2 FROM table_name;
SELECT name, age FROM students; -- Select all columns SELECT * FROM students;
  • Use SELECT * to fetch every column
  • Always specify columns in production for performance
  • Column aliases: SELECT name AS student_name
🔍
02 · FILTER
WHERE
Where — Filter Rows
Filters rows before any grouping. Applied to individual rows.
onlycondition greater thanless than equalsspecific value
SELECT * FROM table WHERE condition;
SELECT * FROM students WHERE age > 18; SELECT * FROM employees WHERE dept = 'HR' AND salary > 50000;
  • WHERE runs before GROUP BY — can't filter aggregates here
  • Use AND / OR to combine multiple conditions
  • Use IN: WHERE city IN ('Delhi','Mumbai')
📦
03 · GROUP
GROUP BY
Group By — Bucket Rows
Groups rows with the same value so aggregate functions can be applied per group.
eachper for everygroup-wise by category
SELECT column, AGG_FUNC() FROM table GROUP BY column;
SELECT city, COUNT(*) FROM students GROUP BY city;
  • Every non-aggregate SELECT column must appear in GROUP BY
  • Use with MIN, MAX, SUM, AVG, COUNT for group summaries
  • Add HAVING after to filter the resulting groups
🧹
04 · FILTER GROUPS
HAVING
Having — Filter Groups
Filters after grouping. Used when WHERE can't filter aggregates.
having more than groups with only categories where
GROUP BY column HAVING condition;
SELECT city, COUNT(*) FROM students GROUP BY city HAVING COUNT(*) > 5;
  • WHERE filters rows; HAVING filters groups — don't mix them up
  • You can use any aggregate function in HAVING
  • Always comes after GROUP BY, before ORDER BY
↕️
05 · SORT
ORDER BY
Order By — Sort Results
Sorts the result set in ascending or descending order by one or more columns.
highestlowest topbottom sortedascending
ORDER BY column ASC|DESC;
-- Highest first SELECT * FROM students ORDER BY age DESC; -- Lowest first SELECT * FROM products ORDER BY price ASC;
  • Default is ASC — you can omit it
  • Sort by multiple columns: ORDER BY city, age DESC
  • Combine with LIMIT to get Top-N results
✂️
06 · RESTRICT
LIMIT
Limit — Top N Rows
Restricts the number of rows returned. Essential for Top-N queries.
top 1first 5 only fewhighest one
LIMIT n; LIMIT n OFFSET m; -- skip m rows
-- Top 3 students by marks SELECT * FROM students ORDER BY marks DESC LIMIT 3; -- 2nd highest salary SELECT DISTINCT salary FROM employees ORDER BY salary DESC LIMIT 1 OFFSET 1;
  • Always pair with ORDER BY — otherwise rows are random
  • OFFSET 1 skips first row — useful for 2nd highest
  • SQL Server uses TOP n instead of LIMIT
🔗
07 · JOIN
JOIN
Join — Connect Tables
Combines rows from two or more tables based on a related column.
combine tablesmatch records related datacustomer + order
SELECT * FROM A JOIN B ON A.id = B.id;
SELECT * FROM Orders JOIN Customers ON Orders.customer_id = Customers.id;
  • INNER JOIN → only matching rows
  • LEFT JOIN → all from left table + matches from right
  • RIGHT JOIN → all from right table + matches from left
  • FULL OUTER JOIN → all rows from both tables
🪆
08 · NESTED
SUBQUERY
Subquery — Query Inside Query
A query nested inside another query. The inner query runs first and its result is used by the outer query.
greater than average compared to based on result of dynamic condition
SELECT * FROM table WHERE col > (SELECT ...);
SELECT * FROM employees WHERE salary > ( SELECT AVG(salary) FROM employees );
  • Inner query executes first, result is used by outer query
  • Can appear in WHERE, FROM, or SELECT clause
  • CTEs (WITH clause) are often cleaner for complex subqueries
✅
09 · CHECK
EXISTS
Exists — Check Presence
Returns TRUE if the subquery returns at least one row. Stops scanning as soon as a match is found.
if existshas orders availablepresent in
WHERE EXISTS ( SELECT 1 FROM table WHERE condition );
SELECT * FROM customers c WHERE EXISTS ( SELECT 1 FROM orders o WHERE o.customer_id = c.id );
  • Faster than IN for large datasets — stops at first match
  • Use SELECT 1 inside EXISTS — the value doesn't matter
  • NOT EXISTS = find rows with no match in another table
🔀
10 · LOGIC
CASE WHEN
Case — If-Else in SQL
Conditional logic inside a query. Like an if-else statement that returns values.
gradecategory classifylabel if condition
CASE WHEN condition THEN result WHEN condition THEN result ELSE default_result END
SELECT name, CASE WHEN marks >= 90 THEN 'A' WHEN marks >= 75 THEN 'B' ELSE 'C' END AS grade FROM students;
  • CASE can be used inside SELECT, WHERE, ORDER BY
  • Always close with END and optionally alias it
  • Conditions are checked top-down — first match wins
🪟
11 · ANALYTICS
OVER()
Window Functions — Rank & Analytics
Calculations across rows without collapsing them. The most powerful SQL feature for analytics.
rankrunning total row numberpartition top per group
FUNCTION() OVER ( PARTITION BY column ORDER BY column )
-- Rank by salary SELECT name, RANK() OVER ( ORDER BY salary DESC ) AS rnk FROM employees; -- Running total SELECT name, salary, SUM(salary) OVER ( ORDER BY id ) AS running_total FROM employees;
  • RANK() — leaves gaps after ties (1,1,3)
  • DENSE_RANK() — no gaps (1,1,2)
  • ROW_NUMBER() — unique row number always
  • LAG/LEAD — access previous/next row values
  • PARTITION BY = GROUP BY equivalent for windows
🧮
12 · AGGREGATE
AGG FUNCS
Aggregates — Math on Data
Built-in functions that perform calculations on a set of rows and return a single value.
totalmaximum minimumaverage how manyoverall
MIN(col) → smallest value MAX(col) → largest value SUM(col) → total AVG(col) → average COUNT(*) → number of rows
SELECT MIN(salary) AS min_sal, MAX(salary) AS max_sal, SUM(salary) AS total, AVG(salary) AS average, COUNT(*) AS headcount FROM employees;
  • COUNT(*) counts all rows; COUNT(col) skips NULLs
  • AVG also ignores NULL values automatically
  • Always use GROUP BY to get aggregates per category
  • Can be used inside WINDOW functions with OVER()
